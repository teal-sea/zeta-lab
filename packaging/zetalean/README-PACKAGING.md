# ZetaLean as a standalone Reservoir package — prep kit

**Status: PREP ONLY. Nothing here is public-facing until Tom creates the
standalone repository and pushes this content to it.** Reservoir indexes
automatically once its criteria are met, so creating that repo IS the
publish switch — treat it accordingly.

## Why a separate repo

Reservoir requires `lake-manifest.json` at the TOP LEVEL of the
repository; zeta-lab's Lean lives under `lean/`, so in-place indexing is
not possible. The standalone repo (suggested: `teal-sea/zetalean`) gets
the `lean/` package contents at its root, with zeta-lab remaining the
laboratory of record. Sync direction is one-way, lab -> package, at
tagged releases.

## Checklist (each step reversible until the last)

1. Create `teal-sea/zetalean` (public). Copy the contents of `lean/`
   to its root: `ZetaLean/`, `ZetaLean.lean`, `lakefile.toml` (below),
   `lean-toolchain`, `lake-manifest.json` (generated by `lake update`),
   `LICENSE` (MIT, from zeta-lab root), `README.md` (below).
2. Confirm `lake build` green from a fresh clone (the CI file below does
   this on every push).
3. Tag `v0.1.0`. Reservoir needs an OSI license (MIT: yes) and 2 GitHub
   stars; indexing then happens on Reservoir's crawl — no application.
4. Consumers then write, in their lakefile:
       [[require]]
       name = "ZetaLean"
       scope = "teal-sea"
   That is the whole distribution story: no queue, no reviewer.
